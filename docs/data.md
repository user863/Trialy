# Trialy data

The pipeline turns ClinicalTrials.gov records into one JSON bundle per disease group. The web app and any other reader use the same file. Today there are two groups:

- `lung`: lung cancer, with a disease-specific rule reader (about 16% of criteria structured).
- `ms`: multiple sclerosis, with a reader for the most common criteria (about 17% structured): MS course, EDSS range, recent relapse windows, earlier drug classes, and yes/no exclusions for pregnancy or breastfeeding, MRI contraindications, recent steroids, HIV/hepatitis/tuberculosis and cancer history. Every sentence is kept verbatim; what the reader does not fully understand stays `other`. Timed or conditional sentences are weakened with `narrow` so they can leave a criterion open but never hide a trial on their own.

A group is defined in `packages/pipeline/src/groups.ts` (registry query, condition filter, whether it is general).

## Files

| file | contents |
|---|---|
| `<group>.json` | the bundle: trials, criteria, rules |
| `manifest.json` | all groups with bundle version and trial count; each pipeline run updates its own entry |
| `index.json` | tier 1: every trial of every group without its free text, for matching and the result list |
| `details/NNN.json` | tier 2: the free text and contact details, grouped into shared buckets |
| `postcodes.json` | postcode to coordinates for DE, AT, CH, NL, BE, LU, FR, DK, PL, CZ |
| `schema/bundle.schema.json` | JSON Schema of the bundle |
| `schema/index.schema.json` | JSON Schema of `index.json` |
| `schema/details.schema.json` | JSON Schema of one `details/NNN.json` |
| `schema/rule.schema.json` | JSON Schema of a single rule |
| `schema/profile.schema.json` | JSON Schema of the patient profile (used by the app, not part of the bundle) |

## Bundle format

Top level:

| field | type | meaning |
|---|---|---|
| `group` | string | group id, e.g. `lung` |
| `groupLabel` | string | display name |
| `version` | string | see Versioning |
| `generatedAt` | ISO 8601 | when the pipeline ran |
| `source` | string | `ClinicalTrials.gov API v2` |
| `trials` | Trial[] | |
| `changes` | object | `since` (previous version or null), `added` and `removed` NCT ids |

Trial (one registry record):

| field | notes |
|---|---|
| `nctId`, `otherIds` | registry id; EU CT, EudraCT and DRKS ids when the record lists them |
| `title`, `officialTitle`, `briefSummary` | registry text, unchanged |
| `status` | `RECRUITING`, `NOT_YET_RECRUITING`, or `OTHER`. The bundle only holds the first two at build time |
| `phases`, `conditions`, `interventions`, `armLabels`, `design` | from the record |
| `lastUpdated`, `statusVerified` | registry dates |
| `centralContact` | name, email, phone as listed in the record |
| `sites[]` | facility, city, country, zip, site status, `lat`/`lon` (the registry's `geoPoint`), contact fields as listed |
| `eligibilityText` | registry eligibility text, unchanged |
| `criteria[]` | the eligibility text split into one entry per criterion |

Criterion:

| field | notes |
|---|---|
| `id` | `<nctId>-<index>` |
| `kind` | `inclusion` or `exclusion` |
| `text` | the criterion as written in the registry |
| `rule` | machine-readable form, see below |
| `source` | `registry-text` (extracted from the text) or `registry-field` (built from a structured field such as age) |
| `confidence` | `high`, `low`, or `none` |

Rule: a tagged union (`_tag`) of typed rules (cancer type, stage, biomarker, PD-L1, prior therapy, lines, current therapy, lab, age, sex, performance status, flag, MS course, EDSS, relapse, MS drug class) plus `anyOf`, `allOf`, `not`, `narrow` and a catch-all `other`. Anything the extractor does not fully understand is `other`, and the original `text` is shown to the user. A rule evaluates to yes, no or unknown (Kleene logic); unknown never excludes a trial. In the `lung` bundle about 16% of criteria are structured; the rest are `other`. In a general group none of the text criteria are.

The rules and the criterion split are generated by Trialy's extractor. They are not clinically reviewed and not a statement by the registry or the trial sponsor.

## Index and details (what the web app loads)

The bundle is the complete record and the format for reuse. The web app does not load it. It loads two derived layers so that the first download is small and does not depend on what a visitor is looking for:

- **Tier 1, `index.json`.** One file for all groups, the same for every visitor. Per trial: title, status, phases, conditions, intervention types, dates, sites (an index into a shared site table plus the site's recruitment status), the structured rules, the registry age and sex criteria, and for every other criterion only its kind. The free text is not in it. The index is enough to match, rank and sort by distance, and to draw a result card.
- **Tier 2, `details/NNN.json`.** The brief summary, the verbatim eligibility text and criterion lines, intervention names, arms, design, contacts and zip codes. Trials are assigned to a bucket by a hash of the NCT id (`bucketOf` in `packages/domain/src/tiered.ts`), so a bucket mixes trials from every group. The number of buckets is `bucketCountFor(trials)`: about 200 trials per bucket, at most 256. The client fetches a bucket only when a trial is opened.

`splitTrial` and `joinTrial` convert between a bundle trial and the two layers. The pipeline rebuilds every trial from the layers and fails if one differs, so nothing is lost in the split.

Sites without coordinates in the registry are filled in the pipeline (`packages/pipeline/src/locations.ts`): from the same hospital in another trial, otherwise from the centre of the same city if all known sites there lie within 50 km of it. A site located from a city centre carries `approxLocation: true`. Sites that cannot be placed stay without coordinates and sort last by distance.

`npm run pipeline -- --reindex` rebuilds the site coordinates, `postcodes.json`, `index.json` and the detail buckets from the bundles on disk without fetching anything.

## JSON Schema

`npm run schema` regenerates `packages/domain/schema/*.json` from the Effect Schema in `packages/domain/src/schema.ts`. A test validates the committed bundle against them with ajv, so the schema and the data cannot drift apart silently.

Validate a bundle elsewhere:

```bash
npx ajv-cli validate -s schema/bundle.schema.json -d lung.json --strict=false
```

## Versioning

- `version` is the UTC time of the pipeline run as `YYYYMMDDHHmm`, for example `202610122117`. Newer versions sort higher.
- `changes` lists NCT ids added and removed since the previous version.
- The data format is defined by the schema files at the same commit. A release ships the schema files next to the bundle. If a field changes in a way that breaks readers, the release notes say so.
- Releases are tagged `data-<group>-<version>`. `npm run release:data` builds the archive locally; publishing is a separate manual step.

## Data terms

The code is Apache-2.0. The licence does not cover the data below, which stays under its sources' terms.

**ClinicalTrials.gov** (trial records in the bundle). Terms: https://clinicaltrials.gov/about-site/terms-conditions. Summary of what they ask of reusers:
- attribute the source as ClinicalTrials.gov;
- show the date the data was processed (`generatedAt`) and keep it current;
- say what was modified: here the criteria are split, `rule`, `source` and `confidence` are added, status values outside RECRUITING/NOT_YET_RECRUITING become `OTHER`, and records are filtered by condition, country and age;
- some content may belong to third parties; check with them for extra terms.

Records contain contact names, emails and phone numbers as submitted to the registry. Link to the live record (`https://clinicaltrials.gov/study/<nctId>`) for the authoritative version.

**GeoNames** (postcode table in the web app, ten countries). CC BY 4.0, https://www.geonames.org/. Credit GeoNames when you reuse the tables. They are not part of the bundle release.

**Natural Earth** (map outline via `world-atlas`, web app only). Public domain.
